# VoxType 0.10.4 发布审计

日期：2026-08-01

## 版本判断

本次从 `0.10.3` 升到 `0.10.4`。改动只修复主窗口底部错误通知的生命周期并补充对应测试与用户说明；不新增配置字段、不改变数据格式、默认策略或语音输入主链路，因此按项目版本策略升级 patch。

## 根因与行为

- 原通知策略对所有 `error` 返回永久保留，后续录音成功或开始新一轮时没有推进或清理该通知，因此一次偶发空识别等错误会无限期占据首页底部。
- 主窗口仍只保存并显示最新一条通知，不增加错误历史列表。
- 新错误获得五轮内存窗口，错误发生轮计入第 1 轮；错误可在第 N 至 N+4 轮显示，到第 N+5 轮开始时清除。
- 新错误替换旧错误并重新获得完整五轮；手动关闭继续立即生效。成功、信息和警告仍使用原有定时策略，错误不增加固定秒数超时。
- 只有 `idle`、`succeeded` 或 `failed` 进入 `starting` 或直接进入 `recording` 才算新一轮；`starting -> recording`、重复 phase 和处理中迟到状态不重复扣减。

## 实现范围

- `notificationController.svelte.ts` 保存当前错误剩余轮数并在轮数耗尽时复用现有 `clear()`。
- `sessionState.ts` 提供可独立测试的新录音边沿判断；主 controller 在现有 phase 组合点推进通知轮次。
- 更新通知与会话状态单元测试、中英文 README、功能 Wiki 草稿、CHANGELOG、版本元数据和本发布审计；不新增依赖、配置或用户可见文案 key。

## 主链路、配置与隐私

- 不修改 Rust 录音会话状态机、ASR 请求、空识别失败门禁、最终包选择、LLM 润色、剪贴板写入与恢复、最近上下文、自动热词或成功统计。
- 不新增或修改配置字段和默认值，不改变热键、托盘、悬浮字幕 DOM 或通知样式。
- 五轮计数只存在于当前主窗口内存；不写入配置、日志、诊断、统计或其他本地文件，也不记录识别正文、密钥、热词、prompt、最近上下文或 Windows 用户名路径。

## 建议手工回归

- 制造一次空识别错误，确认底部错误通知可见且关闭按钮仍立即生效。
- 从错误发生轮开始连续录音，确认第 N 至 N+4 轮通知仍可保留，第 N+5 轮开始时清除。
- 在保留窗口内制造新错误，确认只显示最新错误并从新错误重新计算五轮。
- 复测正常识别、配置错误、警告和普通成功提示，确认 ASR、润色、粘贴与统计行为没有变化。
