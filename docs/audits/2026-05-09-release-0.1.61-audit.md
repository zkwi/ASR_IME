## 范围

- 修复安装版“测试 OCR”在 Tauri 命令线程上触发 Windows OCR 初始化失败的问题。
- 版本号、CHANGELOG、发布检查和安装包产物。

## 根因

- `0x80010106` 是 Windows `RPC_E_CHANGED_MODE`，表示当前线程已经被初始化为另一种 COM/WinRT apartment 模式。
- `0.1.60` 的测试按钮直接在 Tauri 命令线程调用 `RoInitialize(RO_INIT_MULTITHREADED)`；安装版里该线程可能已经是单线程 apartment，因此会直接报错。

## 结论

- “测试 OCR”现在会在独立工作线程调用 Windows OCR，避免受 Tauri 命令线程 apartment 模式影响。
- 如果未来从已初始化线程调用 OCR，`RPC_E_CHANGED_MODE` 会被视为已有可用 apartment，不再作为初始化失败；这种情况下不会额外调用 `RoUninitialize`。
- 主录音链路、ASR 请求、LLM prompt、剪贴板、热键、托盘和隐私边界未改变。
- OCR 正文仍不写入日志、统计、诊断报告或配置文件。
- 临时 smoke 覆盖了“调用线程已是单线程 WinRT apartment，再通过 worker 测试 OCR”的场景：当前窗口识别 362 字，用时 133ms，语言 `zh-Hans-CN`。
- `npm run ai:check` 通过。
- `npm run ai:release-check` 通过；Rust 审计仅报告当前 Tauri 依赖链中已允许的 19 条上游 warning。
