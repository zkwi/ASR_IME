# VoxType 0.7.1 发布审计

日期：2026-07-07

## 版本判断

本次从 `0.7.0` 升到 `0.7.1`。原因是修复 `0.7.0` 新增的大模型自动适配触发漏接问题，属于小范围 hotfix，按版本策略递增 patch。

## 问题原因

`0.7.0` 将大模型自动适配挂在 `VoxTypeController.persistConfig()` 外层包装中，但设置页的自动保存实际由 `configController` 内部直接调用自己的 `persistConfig()`。因此用户修改模型名并等待自动保存时，配置会保存成功，但不会进入自动适配队列。

## 修复内容

- `configController` 增加保存成功回调 `onConfigSaved`。
- `VoxTypeController` 将 LLM 自动适配队列挂到该回调上，确保自动保存和手动保存都会触发同一条保存后处理链路。
- 外层 `persistConfig()` 不再重复触发队列，避免手动测试保存策略时产生二次处理。

## 主链路审计

- 本次只改前端保存后处理链路，不改 Rust ASR、LLM 请求体、剪贴板、热键、托盘、统计或日志。
- 自动适配仍只在 Base URL、API Key、模型名或 thinking 开关指纹变化且三项连接配置完整时触发。
- 自动适配测试仍使用内置连接测试样例，不读取最近上下文正文。

## 验证重点

- 修改大模型模型名后，自动保存成功应触发 `testingLlm` 状态和自动适配测试。
- 手动点击大模型测试仍可保存最快成功 `thinking_strategy`。
- 修改非大模型配置不应触发 LLM 自动适配。
