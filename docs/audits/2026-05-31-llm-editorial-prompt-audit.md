# 2026-05-31 LLM 成稿化提示词复测审计

本记录说明一次面向 VoxType 默认大模型润色提示词的复测与轻量优化。测试使用本机已配置的大模型服务和合成样例，不包含真实 API Key、真实识别正文、本地最近上下文、热词、屏幕 OCR 正文、日志或统计正文。

## 目标

- 让长段口述不再只是轻量校对，而是更像正式记录、复盘或说明。
- 允许长文本适当改写、补自然连接、调整句序和分段。
- 保留原文事实、判断、语气强弱和立场，不新增信息，不回答问题。
- 保持短消息、技术路径、函数名和提示词样式文本的基本边界。

## 临时测试结论

- 当前默认提示词在短消息、技术路径和提示词样式文本上较稳，但对长文本偏保守，育儿记录、投资复盘、会议纪要、产品反馈和个人计划多数仍输出为单段。
- 只在 User Prompt 中加入“必要时分段”力度不足，模型仍倾向单段轻润色。
- 过于激进的“强制长文本分段”会提升长文本成稿感，但中等长度工作说明可能仍单段，且个别短句会补句号；这在本轮需求中可接受。
- 综合效果最好的是“先判断文本类型”的策略：短消息和技术说明保持轻量，长段口述、记录、复盘、说明、会议纪要、产品反馈和投资复盘按正式正文处理，默认整理为 2-4 个自然段。

## 改动范围

- 默认 System Prompt 增强文本类型判断和长文本成稿化规则。
- 默认 System Prompt 明确长文本可删除口水词、语气垫词、重复表达、无效停顿和自我修正过程，并可调整语序、拆分句子、补足必要连接词。
- 默认 System Prompt 明确长文本默认输出 2-4 个自然段，每段一个中心。
- 默认 User Prompt Template 同步强调长文本按正式正文处理，保留事实、判断、语气强弱和立场。
- 配置样例、前端默认值、README、英文 README 和 Wiki 草稿同步说明。

## 未改变内容

- 不新增配置字段。
- 不改 LLM 模型、Base URL、API Key、`thinking_strategy`、`max_tokens` 或超时。
- 不改 ASR 请求协议、空识别失败态、LLM 润色触发条件、剪贴板输出、热键默认值、托盘行为、日志脱敏或统计正文策略。
- 不提交临时测试脚本、临时结果文件或本地 `config.toml` 备份。

## 建议回归

- 用短消息测试，确认不会被拆成多段。
- 用育儿记录、投资复盘、会议纪要和产品反馈类长文本测试，确认默认输出更像正式正文。
- 用带屏幕 OCR 路径、文件名或代码标识符的样例测试，确认技术词形仍可借参考信息纠正。
- 用问题或提示词样式文本测试，确认只润色文本，不回答、不执行。
