# VoxType 0.10.1 发布审计

日期：2026-07-23

## 版本判断

本次从 `0.10.0` 升到 `0.10.1`。改动修复刚发布的大模型测试与 OpenRouter 思考适配兼容问题，不新增配置字段、不改变主功能定位，也没有破坏性迁移，因此按项目版本策略升级 patch。

## 根因与复现证据

- OpenRouter 的 `tencent/hy3` 模型默认启用高强度 reasoning，只接受 `high`、`low` 和 `none`；原自动适配候选没有发送真正的关闭值 `none`。
- 使用原 256-token 测试上限时，原有 `minimal`、`low` 和 `enable_thinking=false` 候选均得到 HTTP 200，但 completion token 被思考过程耗尽，最终 `content` 为空并以 `length` 结束。
- OpenRouter 当前把可见思考内容放在 `message.reasoning`，原解析只识别兼容字段 `reasoning_content`。
- 将唯一变量改成 `reasoning.effort=none` 后，同一模型在原 256-token 上限内返回最终正文并正常结束，证明失败来自适配参数与输出判定，而不是 Base URL、模型 ID 或网络链路。

现场测试只记录状态码、耗时、字段是否存在、字符数和结束原因；审计、日志、测试和代码均不包含用户 API Key、账户详情、请求正文或模型返回正文。

## 实现范围

- 新增 `openrouter_reasoning_none` 合法策略，发送 `reasoning: { effort: "none", exclude: true }`。
- OpenRouter 非 StepFun 模型在关闭思考和自动适配时优先尝试 reasoning none，再回退 minimal 和 low；StepFun 等既有强制思考例外继续优先 low。
- OpenRouter 不支持统一 reasoning 字段时，保留原有“移除不支持字段后重试”能力；强制思考模型拒绝 none 时继续尝试低档候选。
- 响应解析兼容 `message.reasoning`，但连接测试只有拿到最终 `content` 才算可用于润色。
- 对“思考内容耗尽输出额度”“只有思考内容”“普通空响应”给出不同提示，说明原因和下一步。
- 高级兼容性设置新增三语言 `OpenRouter reasoning none` 选项；配置字段名和默认值不变，旧配置继续兼容。

## 主链路、配置与隐私审计

- 只影响 LLM 连接测试和关闭思考时的 OpenRouter 请求参数；不修改录音、ASR 最终包、字幕、剪贴板粘贴与恢复、最近上下文、自动热词或成功统计链路。
- 不新增 `config.toml` 字段，只扩展 `llm_post_edit.thinking_strategy` 的合法枚举值，并同步配置模板、前端设置项、三语言文案、README 与 Wiki。
- 不记录真实密钥、润色正文、思考正文、prompt、最近上下文或屏幕 OCR；日志仍只记录模型名、策略、耗时和脱敏错误摘要。

- 先证明截断的 reasoning-only 响应会被误判可用，再要求最终正文并增加耗尽提示。

- `npm run ai:check`：通过；45 项 Vitest 和 241 项 Rust 测试全部成功。

## 建议手工回归

- 使用新的 OpenRouter API Key、Base URL `https://openrouter.ai/api/v1` 和模型 `tencent/hy3`，保持思考关闭与自动适配，确认连接测试成功并保存 `openrouter_reasoning_none`。
- 输入达到 `min_chars` 的中长文本，确认实际润色返回最终正文，不再回退原文或提示空内容。
- 手动选择 OpenRouter low/minimal，确认只有思考内容且输出额度耗尽时会显示明确原因，不会误报测试成功。
- 使用一个强制思考模型确认 none 被拒绝后仍会尝试低档候选；复测 DashScope 与 DeepSeek，确认既有关闭方式未回退。

真实录音、自动粘贴、不同 OpenRouter 强制思考模型和安装包安装运行仍需在用户环境中手工回归；自动测试不使用或保存用户云端凭据。
