# VoxType 0.8.3 发布审计

日期：2026-07-18

## 版本判断

本次从 `0.8.2` 升到 `0.8.3`。改动修复阿里云 FunASR 实时字幕在跨分句时丢失已确认前文的问题，属于单一服务商的小范围用户可见缺陷修复；不涉及配置迁移、数据格式变化、安装路径变化或主链路兼容性，按项目版本策略使用 patch 版本。

## 根因与修复

- FunASR 的 `result-generated` 事件按当前分句返回；原显示事件直接转发这一句，`sentence_end=true` 后虽然已把分句保存到最终文本门禁，但下一句 partial/stable 不包含此前已确认内容。
- 悬浮字幕因此在每个新分句开始时退回只显示当前短句，即使整段识别内容已足够使用两行，前端也只能按收到的短文本显示一行。
- `AliyunFinalGate` 现在只为显示事件组合“已确认分句 + 当前未完成分句”；最终文本仍由已确认分句组成，并继续受 `task-finished` 门禁保护。
- 全局单/双行阈值、DOM、CSS、窗口尺寸、字号算法和通用字幕节流均未修改。

## 主链路、配置与隐私审计

- 本次只修改 FunASR 实时字幕事件的显示文本，不修改 WebSocket 请求、音频发送、`sentence_end` 判定、停止录音和 `task-finished` 门禁。
- 不改变豆包 ASR、LLM 润色、剪贴板写入与恢复、自动粘贴、最近上下文、自动热词、统计、热键、托盘或日志。
- 不新增配置字段、依赖、用户可见文案 key 或配置迁移。
- 测试使用合成文本；识别正文不写入日志、诊断报告、统计、文档或发布资产。

## 建议手工回归

- 使用 FunASR 连续说出包含两个以上完整分句的长文本，确认第二句开始后字幕仍保留前一句，并在总内容足够时自然显示两行。
- 停录前观察字幕累计更新，确认不会在分句边界退回单句；停录后确认只有收到 `task-finished` 才进入润色或粘贴。
- 分别用短句、无标点长句和中英混合内容回归，确认短文本仍为单行、长文本最多两行。
