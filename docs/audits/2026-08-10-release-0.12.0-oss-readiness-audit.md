# VoxType 0.12.0 OSS 就绪发布审计

日期：2026-08-10

## 版本判断

本次从 `0.11.0` 升到 `0.12.0`。没有新增产品功能或破坏配置兼容，但 GitHub 首页、贡献者入口、CI 拆分、CodeQL、安全报告与依赖治理均为明显、持续可见的项目级升级，符合仓库“正式治理或体验升级优先升 minor”的策略。

## 用户与贡献者可见变化

- README 首屏以英文优先呈现一句话定位、真实截图、Why VoxType、下载、Quick Start 和项目状态，中文与英文长文档继续保持对等入口。
- 新增根目录 `ROADMAP.md`、`ARCHITECTURE.md`、`.github/CODEOWNERS`，并重写双语 `CONTRIBUTING.md` 与 `SECURITY.md`。
- PR 和 Issue 模板明确主链路、配置、隐私、日志、更新器和验证影响；空白 Issue 默认关闭，支持、排障、路线图和私有安全报告均可直接发现。
- 已建立三个真实公开任务：[#32](https://github.com/zkwi/VoxType/issues/32) 英文维护指南、[#33](https://github.com/zkwi/VoxType/issues/33) 干净 Windows 安装烟雾测试、[#34](https://github.com/zkwi/VoxType/issues/34) 更新安装包可信校验设计。

## 安全与依赖结论

- npm 锁文件将 `nanoid 3.3.16` 升到 `3.3.18`，消除 `GHSA-2v37-7h3g-55p8`；`npm audit` 为 0 个已知漏洞。
- Cargo 锁文件将 `event-listener 5.4.1` 升到 `5.4.2`，消除 `RUSTSEC-2026-0221`。
- GitHub Secret Scanning、Push Protection、Dependabot security updates 和 Private Vulnerability Reporting 均已启用。
- 新增 CodeQL 对 JavaScript/TypeScript、Rust 和 Actions 的扫描；所有可复用第三方 Action 固定到完整 commit SHA。
- 详细数据流、Tauri 权限、日志脱敏、截图和更新器审计见 [2026-08-10 OSS 与安全就绪审计](2026-08-10-oss-security-readiness-audit.md)。

## 主链路影响

- 不修改录音、音频分片、ASR provider、最终包选择、LLM 资格、剪贴板、热键、托盘、统计或配置字段与默认值。
- 唯一 Rust 源码变化是删除 OCR 超时测试无法稳定保证的 100ms wall-clock 上界；真实 1ms 超时返回 `None` 的断言保留，定向测试连续 20 次通过。
- 空识别失败、中间包仅反馈、最终包门禁、默认 `200ms` 音频分片、最近上下文/右 Alt/鼠标中键/系统静音默认关闭和自动恢复剪贴板策略均未改变。

## CI 与治理

- CI 拆为质量与回归、npm/Cargo 依赖审计、clippy 与 Tauri debug build 三个 Windows 检查，失败范围可以单独定位。
- CodeQL 独立在 push、PR、周计划和手工触发时运行；工作流顶层只授予内容只读与上传安全结果所需权限。
- Dependabot 继续按 npm、Cargo、GitHub Actions 分流并分组；贡献标签和路线图提供边界明确的 Codex/社区工作。

- `npm run ai:release-check` 通过：Svelte 检查 0 errors/0 warnings，前端生产构建、14 个 Vitest 文件共 61 项、密钥扫描及自测、治理检查及自测、发布前置自测、Rust fmt/check 和 248 项 Rust 测试全部成功。

- `npm run tauri -- build` 通过，正式应用与 NSIS 安装器的 ProductVersion/FileVersion 均为 `0.12.0`。

## 建议手工回归

- 安装版首次启动、主窗口、字幕窗和启动提示窗均能正常显示，外部帮助与下载链接仍能从主窗口打开。
- 使用标准豆包、Agent Plan 或阿里云任一现有配置完成一轮真实麦克风识别，确认最终包后才进入可选润色、粘贴和成功统计。
- 复测空录音、错误凭据、剪贴板写入失败和恢复原剪贴板兜底；日志与诊断不应出现正文、密钥或 Windows 用户名路径。
- 从设置页检查更新，确认 `0.12.0` 不会把自身判断为更高版本；后续版本仍能定位优先级最高的 x64 setup 安装包。
