# VoxType 0.4.2 LLM 最小润色长度热修复审计

日期：2026-07-03

## 问题

- 热词与提示词页直接输入 `min_chars` 后，部分合法值会在配置加载时被旧默认值迁移逻辑重置。
- 根因是 `migrate_llm_min_chars_default` 只按数值判断旧默认值，无法区分旧版本默认配置和用户刚手动输入的合法数值。

## 修复

- 移除 `min_chars` 的按值迁移逻辑，保存过的 `llm_post_edit.min_chars` 一律按用户配置保留。
- 移除 DDC 的旧组合按值迁移，`request.enable_ddc = false` 会按用户配置保留。
- 新安装和缺省配置的 `min_chars` 默认值从 `100` 调整为 `40`。
- 同步 Rust 默认值、前端 fallback、配置模板、三语言设置提示、README、英文 README、Wiki 草稿和 CHANGELOG。

## 主链路审计

- 只影响 LLM 润色触发阈值和配置加载，不改变豆包 ASR、音频采集、最终包等待、剪贴板写入、自动粘贴、统计、热键或托盘逻辑。
- 配置结构不变，不新增字段，不迁移识别正文。
- 不记录密钥、识别正文、热词、Prompt、OCR 正文或最近上下文正文。

## 手工回归建议

- 在热词与提示词页直接输入 `0`、`25`、`40`、`80`、`100`、`120`、`150`，等待自动保存后切换页面或重启应用，确认数值不被重置。
- 新建配置或删除 `llm_post_edit.min_chars` 字段后启动，确认默认显示 `40`。
- 手动关闭语义顺滑 DDC 后重启，确认不会被重新打开。
- 输入 40 个触发单位以下的短文本，确认不显示“正在润色文本”；输入达到阈值且 LLM 配置完整时，确认会进入润色。
