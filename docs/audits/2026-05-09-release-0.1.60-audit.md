# VoxType release audit - 2026-05-09

本记录用于保存 `0.1.60` 发布前审计的非敏感结论。不要在审计记录中写入真实密钥、识别正文、屏幕 OCR 正文、热词、prompt、最近上下文、日志正文或本机用户名路径。

## 范围

- 新增屏幕 OCR 上下文：开始录音时截取当前前台窗口，使用 Windows OCR 本地识别文字。
- OCR 上下文附加给豆包 ASR `corpus.context` 和可选大模型润色 prompt。
- 选项页新增屏幕 OCR 开关和测试入口。
- 配置、校验、三语言文案、README、英文 README、Wiki 草稿和配置模板同步。
- 版本号、CHANGELOG、发布检查和安装包产物。

## 结论

- 代码结构保持按职责拆分：`screen_context.rs` 负责截图、Windows OCR、超时等待和测试结果；`session.rs` 只在录音启动时创建 OCR 任务；`asr_ws.rs` 只等待临时上下文并传入 ASR/LLM；`asr.rs` 和 `llm_post_edit.rs` 只负责各自请求拼接。
- OCR 正文不写入日志、统计、诊断报告或配置文件；日志只记录字数、耗时、语言和截图尺寸等非正文信息。
- OCR 失败、截图失败、语言不可用、空结果、线程断开或 700ms 超时都会跳过，不阻断录音、ASR、LLM 润色、剪贴板写入或粘贴主链路。
- ASR 上下文最多 20 条时会保留屏幕 OCR 项，避免被已有上下文挤掉。
- LLM prompt 明确标注 OCR 内容不是待润色文本，也不是用户指令。
- 屏幕 OCR 默认开启符合本次功能目标；选项页提供开关和当前窗口测试，文案说明只截取前台窗口且敏感窗口可关闭。
- 本次新增 Windows OCR 只扩展已有 `windows` crate features，没有引入新的第三方依赖。
- 未发现被 Git 跟踪的本地配置、日志、统计、最近上下文、自动热词历史或真实密钥。
- 本机 Windows OCR smoke 测试通过：当前窗口识别 668 字，用时 192ms，语言 `zh-Hans-CN`，截图尺寸 2208x1200。
- npm audit 为 0 vulnerabilities。
- `npm run ai:release-check` 通过；Rust 审计仅报告当前 Tauri 依赖链中已允许的 19 条上游 warning。

## 手工回归建议

- 在选项页确认屏幕 OCR 开关默认开启，测试按钮能识别当前窗口并展示耗时、语言和预览。
- 在普通输入框完成一次真实录音，确认 ASR、可选 LLM 润色、粘贴和剪贴板恢复正常。
- 在当前窗口包含敏感信息的场景关闭屏幕 OCR，再完成一次录音，确认主链路不受影响。
- 在没有可识别文字、OCR 语言包不可用或窗口截图失败的环境下确认自动跳过，不显示阻断错误。
