# 2026-05-30 LLM 长文本提示词优化审计

本记录说明一次面向 VoxType 大模型润色默认提示词的轻量优化。测试使用本机已配置的大模型服务和合成样例，不包含真实 API Key、真实识别正文、本地最近上下文、热词、屏幕 OCR 正文、日志或统计正文。

## 目标

- 短文本保持轻量润色，避免不必要扩写或重排。
- 长文本允许在不新增事实、不改变意图的前提下整理口水词、重复表达、无效停顿和口述改口过程。
- 保持提示词注入、问题文本、给其他 AI 的指令文本都只被当作待润色文本，不被回答、执行或解释。
- 保持 OCR 和参考信息边界，降低路径、文件名和代码标识符被误补全的概率。

## 临时测试结论

- 第一组温和规则能保持短文本稳定，但长文本仍容易保留“刚才说法不准确”一类口述修正过程。
- 第二组加入长文本重组规则后，能明显减少口水词和改口残留，但个别样例仍会保留“准确说”或语气词。
- 最终候选在短文本、长段口述、带 OCR 技术文本和消息转述四类合成样例中表现更均衡：短文本不过度处理，长文本能整理重复与改口，技术文本能继续借 OCR 修正路径和代码标识符，且不会主动添加反引号。
- 最终候选的合成样例平均耗时约 2.2 秒，未明显增加实时润色延迟。实际耗时仍取决于模型、网络、服务商和文本长度。

## 改动范围

- 默认 System Prompt 增加短文本和长文本的差异化润色规则。
- 默认 System Prompt 明确长文本可删除口水词、无意义语气词、重复表达、无效停顿和修正过程。
- 默认 System Prompt 明确改口时采用最终意图，不保留改口过程；无法判断时保留原文。
- 默认 System Prompt 明确不要主动添加 Markdown、反引号或其他格式标记，除非原文明确需要代码样式。
- 默认 User Prompt Template 增加一条紧凑的当前请求提醒：短文本轻量纠错，长文本删除口水词、重复和自我修正过程，并避免主动添加 Markdown 或反引号。
- 配置样例、前端默认值、README 和 Wiki 草稿同步说明。

## 未改变内容

- 不新增配置字段。
- 不改 LLM 模型、Base URL、API Key、`thinking_strategy`、`max_tokens` 或超时。
- 不改 ASR 请求协议、空识别失败态、LLM 润色触发条件、剪贴板输出、热键默认值、托盘行为、日志脱敏或统计正文策略。
- 不提交临时测试脚本、临时结果文件或本地 `config.toml` 备份。

## 建议回归

- 用短句测试默认提示词，确认不会扩写或重排。
- 用包含口水词、重复表达和改口的长段口述测试，确认能整理为更清晰的自然文本。
- 用包含屏幕 OCR 路径、文件名或代码标识符的样例测试，确认参考信息只用于纠错，不被当作正文或指令。
- 用问题或提示词样式文本测试，确认只润色文本，不回答、不执行。
