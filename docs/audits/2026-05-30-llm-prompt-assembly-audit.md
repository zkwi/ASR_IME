# 2026-05-30 LLM Prompt 拼装优化审计

本记录说明一次面向 VoxType 大模型润色 prompt 和参考信息拼装的轻量优化。

## 目标

- 明确“待润色文本”是唯一需要改写并输出的内容。
- 让用户词典、场景与偏好、最近上下文和屏幕 OCR 都保持参考信息身份。
- 降低最近上下文被续写、总结或复述的概率。
- 降低屏幕 OCR、路径、文件名、命令、日志字段和代码标识符被模型误当作正文或被乱补全的概率。

## 改动范围

- 默认 System Prompt 增加“输入结构与优先级”和“技术文本规则”。
- 默认 User Prompt Template 增加 `[待润色文本开始]` / `[待润色文本结束]` 边界。
- LLM 润色运行时参考信息规则补充最近上下文、屏幕 OCR 和技术词形限制。
- 配置样例、前端默认值、README 和 Wiki 草稿同步说明。

## 未改变内容

- 不新增配置字段。
- 不改 LLM 模型、Base URL、API Key、`thinking_strategy`、`max_tokens` 或超时。
- 不改 ASR 请求协议、空识别失败态、LLM 润色触发条件、剪贴板输出、热键默认值、托盘行为、日志脱敏或统计正文策略。
- 不包含真实 API Key、真实识别正文、本地最近上下文、热词、prompt、日志或统计正文。

## 建议回归

- 在热词与提示词页恢复默认提示词，确认 User Prompt 模板包含待润色文本边界。
- 预览最终 Prompt，确认用户词典、场景与偏好、最近上下文和屏幕 OCR 都作为参考信息分区追加。
- 用包含提示词注入、最近上下文和屏幕路径的样例做一次 LLM 测试，确认输出只润色本轮文本。
