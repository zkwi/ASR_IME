# VoxType 0.5.0 发布审计

日期：2026-07-07

## 版本号选择

本次从 `0.4.3` 升到 `0.5.0`。原因是新增用户可见的 ASR 服务选择和阿里云 FunASR Realtime 接入，并新增 `[asr]`、`[aliyun_asr]` 配置结构；按项目版本策略属于 minor 功能发布，不适合作为 patch。

## 审计范围

- 豆包 ASR 先进入 provider 封装层，默认 provider 仍为 `doubao`。
- 阿里云 FunASR Realtime 接入同一录音、字幕、最终文本、LLM、剪贴板和统计主链路。
- ASR 配置健康检查、测试连接、错误归类、前端设置页和三语言文案。
- 配置默认值、配置模板、README、英文 README、Wiki 草稿、架构说明和 ASR 守门清单。
- 隐私边界：不记录真实密钥、识别正文、热词、prompt、最近上下文正文、屏幕 OCR 正文或 Windows 用户名路径。

## 关键判断

- 第一步先封装豆包 ASR，不改变豆包默认协议参数、音频分片、最终包选择、空识别失败态、LLM 触发条件、剪贴板输出、热键默认值、托盘行为或统计正文策略。
- 第二步再接入阿里云 FunASR，新增 provider 只在用户选择 `aliyun_fun` 时生效；旧配置缺少 `[asr]` 时按豆包处理。
- 阿里云中间 `result-generated` 只用于悬浮字幕，最终输出必须等待 `task-finished`，缺少最终文本时仍走空识别失败态。
- 阿里云 API Key、Workspace ID、热词、最近上下文、prompt 和 OCR 正文不写入日志或诊断报告。

## 手工回归建议

- 旧豆包配置不新增 `[asr]` 时启动，确认仍按豆包识别、测试和健康检查。
- 选择豆包 ASR 后测试连接，确认 App Key、Access Key、Resource ID 缺失时仍阻断主流程。
- 选择阿里云 FunASR 后测试连接，确认 API Key、Workspace ID 或 WebSocket URL、模型缺失时阻断主流程。
- 分别用豆包和阿里云完成一次短句录音，确认中间字幕只作反馈，最终识别后才触发可选润色、复制、粘贴和统计。
- 断网、错误 Key、提前关闭连接和无语音录音分别进入失败态，不粘贴中间字幕。
