# VoxType 0.10.3 发布审计

日期：2026-07-31

## 版本判断

本次从 `0.10.2` 升到 `0.10.3`。改动继续聚焦悬浮字幕排版：修正过早换行和双行大面积留白，并优化长文本布局性能；不新增配置字段、不改变主链路、默认策略或数据格式，也没有兼容性迁移，因此按项目版本策略升级 patch。

## 需求与审计结论

- 用户反馈双行字幕机械对半拆分后，两行右侧留白过多；首行应在能够完整显示且不产生孤字尾行的前提下尽量使用整行，目标利用率为 `90%` 以上。
- `0.10.2` 的 `75%` 单行阈值会让原本仍能完整放下的内容提前换成两行，放大视觉留白；本轮改为先按真实 Microsoft YaHei 字宽判断是否确实溢出。
- 结构化代码复审未发现主链路、配置、隐私或日志回退。复审额外发现长文本候选切点会反复测量整段后缀：真实浏览器中 1150 字样本单次布局平均约 `77.89ms`、峰值约 `153.60ms`，相对悬浮窗 `250ms` 轮询周期存在卡顿风险。
- 性能问题根因是布局函数遍历所有切点，即使绝大多数切点的第二行已经确定超宽；加入失败测试后，将候选范围裁剪为首行和尾行实际可能放入可视宽度的切点。排版选择规则不变，样本平均耗时降至约 `2.03ms`、峰值约 `2.60ms`。
- 最终复审结论：无 Critical、Important 或 Minor 待修问题，可以发布。

## 实现范围

- 单行优先使用 `20px`；只有 `20px` 确实放不下但 `19px` 能完整显示时才缩至 `19px`，不再用固定填充比例提前换行，也不继续缩至 `18px` 硬撑单行。
- 真正溢出后使用最多两行；在空间允许时选择首行填充率至少 `90%` 的靠后切点，同时为第二行保留至少 3 个非空白字符。
- 双行在总宽度允许时继续使用 `20px`，长文本回到 `18px` 基线，以免字号增大后丢失可见上下文。
- 继续禁止常用闭合标点出现在第二行行首；超出两行容量时保留能完整显示的最长最新尾部，且不横向裁切。
- 长文本候选测量只覆盖可能放入首行或第二行的前后切点，避免测量明显超出可视范围的整段后缀。
- 同步更新中英文 README、功能 Wiki 草稿、CHANGELOG、版本元数据和本发布审计；不新增依赖。

## 主链路、配置与隐私审计

- 只修改前端悬浮字幕的实时预览排版纯函数；不改变 ASR 请求、中间包与最终包边界、最终文本选择、LLM 润色、剪贴板写入与恢复、最近上下文、自动热词或成功统计。
- 不新增或修改配置字段和默认值，既有用户自定义悬浮窗宽高继续生效。
- 不增加日志、诊断或统计字段，不记录识别正文、密钥、热词、prompt、最近上下文或 Windows 用户名路径。

## 测试与真实浏览器验证

- `overlayLayout.test.ts` 共 17 项通过，覆盖真实默认几何、真实溢出后才换行、`19px` 单行边界、双行 `90%` 填充机会、至少 3 字尾行、截图对应混合中英文、标点行首、超长最新尾部、连续标点和长文本测量工作量上限。
- Chromium 使用真实模块、Microsoft YaHei canvas 字宽和 `402×76` 视口验证；文字元素实测 `320×60`，可用宽度 `314px`。截图反馈原句排为 `20px` 双行，首行宽 `305.29px`、利用率 `97.23%`，第二行 3 个字符；元素 `client/scroll` 均为 `320×60`，无横向或纵向溢出。
- 固定种子的 5,000 组中英文、空格和标点组合使用真实字体属性检查：最多两行、无空行、无测量宽度溢出、第二行无常用闭合标点开头、不提前换行、存在合法切点时不遗漏 `90%` 填充机会且尾行不少于 3 字，0 项失败。
- 浏览器控制台 0 错误、0 警告；视觉截图确认首行接近铺满，第二行完整可见。

## 建议手工回归

- 使用默认悬浮窗和较宽自定义窗口，分别口述刚好能放入 `20px`、只能放入 `19px`、刚刚超过单行及明显超过两行的中文，确认切换自然。
- 复测中英文混排、数字、空格、括号、引号和连续标点，确认首行尽量铺满、尾行不少于 3 字且第二行不以闭合标点开头。
- 持续口述长文本，观察实时字幕更新是否流畅，并确认只截取预览尾部；最终粘贴文本仍等待 ASR 最终包且内容不受预览裁切影响。

真实麦克风录音、Tauri 原生悬浮窗和安装包安装运行仍需在用户环境中手工回归；浏览器验证使用通用测试文本，不调用云端 ASR/LLM，也不读取或保存用户凭据。
