# VoxType 0.4.1 麦克风选择热修复审计

日期：2026-07-03

## 问题

- 用户设备列表中存在多个同名 `Microphone`。
- `0.4.0` 保存了 `audio.input_device` 和 `audio.input_device_name`，但录音时优先按 name 匹配，导致同名设备会被解析到第一个同名项，而不是用户实际选择的 index。
- 前端下拉框也优先用 name 反推选中项，并且 option value 使用数字值，存在选中态显示为空的风险。

## 修复

- 后端解析策略改为：
  - 保存的 index 仍存在，且名称与保存 name 一致时，优先使用 index。
  - index 失效但 name 唯一时，才按 name 迁移选择。
  - name 不唯一且 index 失效时，回退系统默认输入设备并提示。
  - 默认设备和回退路径直接使用 `host.default_input_device()`，不再通过同名枚举项反推。
- 前端显示策略改为：
  - 保存 index 有效时优先显示 index 对应设备。
  - name 不唯一时不静默选中第一个同名设备。
  - 下拉 option value 统一使用字符串，避免选择后显示为空。

## 主链路审计

- 只影响麦克风设备选择和当前设备显示，不改变 ASR 请求、音频分片、LLM、剪贴板、统计或热键策略。
- 不新增配置字段，不迁移配置结构。
- 不记录识别正文、密钥、热词、Prompt、OCR 正文或最近上下文正文。

## 手工回归建议

- 打开选项页，在存在 `0: Microphone` 和 `2: Microphone` 的机器上分别选择两个同名设备，保存后下拉框应继续显示所选项。
- 选择“默认输入设备”后开始录音，应使用系统默认输入设备，而不是第一个同名枚举项。
- 拔掉已保存设备后开始录音，应回退默认麦克风并显示非阻塞提示。
