# VoxType 0.10.2 发布审计

日期：2026-07-31

## 版本判断

本次从 `0.10.1` 升到 `0.10.2`。改动集中修复悬浮字幕单行过满、两行不平衡和长文本尾部裁切，不新增配置字段、不改变主链路或默认功能策略，也没有兼容性迁移，因此按项目版本策略升级 patch。

## 根因与审计发现

- 原布局使用固定 18 字判断单行或双行，没有把文字区真实宽度纳入单行阈值；文字虽然未超过字数上限，视觉上可能已经塞满整行。
- 原贪心换行会把 21 字左右的文本拆成「满行 + 一两个字」，超出两行后直接取最后两条贪心结果，还可能只保留半行上下文。
- 待发布差异最初把 `460px` 误写为仓库默认宽度；实际仓库默认悬浮窗为 `350×64`，浏览器实测默认文字内容区为 `262×48`。`460px` 是较宽配置示例，对应文字内容区 `372×72`。
- 待发布实现只在存在其他可行切点时避开标点行首。使用 Microsoft YaHei 实测 `一二三四五，六七八九` 的恰好满行场景，第二行仍会以逗号开头。
- 原最长尾部二分只判断贪心换行数量。连续标点可被附加到已经满宽的行末，使换行数仍为两行但真实宽度已经溢出；最小字号下最终会退化成一条超宽单行并裁掉正文。

## 实现范围

- 单行同时受 18 字上限和可用宽度 75% 阈值约束；超过任一阈值且高度允许时使用两行，不再靠缩小单行字号硬撑。
- 两行按 canvas 实测字宽选择平衡切点，而不是按字符数或贪心结果拆分；混合中英文时也以显示宽度为准。
- 完整文本只有标点行首切点可用时，逐级缩小双行字号寻找合法切点；超长文本则直接比较两段真实宽度，保留能完整显示的最长最新尾部。
- 尾部截取不会人为制造新的标点行首；无法保留全部上下文时优先保证最新正文完整可见，不横向溢出。
- 同步更新中英文 README、功能 Wiki 草稿和 CHANGELOG；不新增依赖或用户配置。
- 首次发布门禁发现新纳入 npm 审计范围的 SvelteKit 与 PostCSS 公告；在现有 semver 范围内刷新锁定版本到 `@sveltejs/kit 2.70.2`、`postcss 8.5.25` 和 `nanoid 3.3.16`，未改 manifest 版本范围、未使用 `--force`。

## 主链路、配置与隐私审计

- 只修改前端悬浮字幕的实时预览排版；不改变 ASR 请求、中间包与最终包边界、最终文本选择、LLM 润色、剪贴板写入和恢复、最近上下文、自动热词或成功统计。
- 不新增或修改配置字段和默认值。仓库默认悬浮窗仍为 `350×64`，既有用户自定义宽高继续按原配置生效。
- 不增加日志、诊断或统计字段，不记录识别正文、密钥、热词、prompt、最近上下文或 Windows 用户名路径。

## 定向测试与浏览器验证

- `overlayLayout.test.ts` 共 14 项通过，覆盖真实默认几何阈值、按混合字宽平衡、单行 75% 阈值、不缩小字号硬撑单行、孤字尾行、标点行首、最长尾部和连续标点不溢出。
- `npm run check` 通过，Svelte 检查为 0 错误、0 警告。
- Chromium 中导入真实 `overlayLayout.ts`，使用 Microsoft YaHei canvas 测量并按真实 DOM 渲染；`460×88` 视口下文字内容区实测为 `372×72`，状态短句、普通短句、平衡双行、原孤字场景和超长尾部均完整可见，父容器无纵向滚动，控制台 0 错误、0 警告。
- 使用固定种子的 5,000 组中英文、空格和标点组合做浏览器属性检查；最多两行、每行不超过测量宽度、第二行不以常用标点开头且不存在空行，0 项失败。
- 444 字混合文本在同一浏览器中连续布局 100 次，平均约 `9.43ms`，低于悬浮窗 `250ms` 轮询周期。

## 建议手工回归

- 使用默认 `350×64` 悬浮窗口述 9 字、10 字和更长中文，确认从单行到双行的切换自然，两行没有纵向裁切。
- 使用约 `460×88` 的较宽配置复测 13 字、14 字、18 字、21 字和持续长句，确认不会出现塞满单行、孤字尾行或上下文只剩半行。
- 口述包含中文逗号、句号、引号、括号及中英文混排的句子，确认第二行不以闭合标点开头，内容不横向裁切。
- 连续口述超过两行容量的内容，确认字幕稳定保留最新尾部，最终粘贴文本仍等待 ASR 最终包且不受预览截取影响。

真实麦克风录音、Tauri 原生悬浮窗和安装包安装运行仍需在用户环境中手工回归；浏览器验证使用通用测试文本，不调用云端 ASR/LLM，也不读取或保存用户凭据。
