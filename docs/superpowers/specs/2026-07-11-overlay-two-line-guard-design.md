# 悬浮字幕双行保障设计

## 目标

修复两类会让用户看到“长字幕突然只剩一行”的边界情况：旧配置将悬浮窗高度设得过低，以及同一识别会话中的完整实时字幕被异常短中间包覆盖。

## 方案

1. 将悬浮窗运行时有效高度下限固定为 `52px`。窗口上下内边距共占 `16px`，剩余 `36px` 可容纳两行 `14px * 1.18` 的文字。保存新配置时也拒绝低于 `52px` 的高度；旧配置仍可加载，但显示窗口会自动钳制到 `52px`，不修改用户配置文件。
2. `LiveCaptionBuffer` 在当前字幕至少 8 字、下一条比当前少至少 6 字且下一条不超过 4 字时，保留当前字幕。缓冲实例只存在于单次录音会话，不影响下一次录音；最终 ASR 包仍绕过该实时字幕保护，继续由原有最终包门禁处理。
3. 不拼接不重合的中间包，不恢复滚动、历史排版锁或其他布局状态，避免重复文本和新的边界条件。

## 影响范围

- Rust 悬浮窗尺寸与配置校验。
- Rust 实时字幕缓冲。
- 字幕布局、配置和缓冲回归测试。
- README、配置模板、CHANGELOG 和发布审计。

不改变 ASR 最终结果、LLM 润色、剪贴板、自动粘贴、统计、热键、托盘和日志内容。

## 验收标准

- 高度为 `40-51px` 的旧配置实际按 `52px` 显示，长字幕可使用两行。
- 新保存配置不接受低于 `52px` 的悬浮窗高度。
- 较长实时字幕不会被 1-4 字的异常非重合中间包覆盖。
- 正常的较完整修订仍可更新实时字幕。
- 前端布局测试、Rust 测试、`npm run ai:check`、`npm run ai:release-check` 和 Tauri 安装包构建通过。
