# 错误通知最近五轮保留设计

## 目标

修复首页底部错误通知永久驻留的问题。错误仍应给用户足够的查看和手动处理时间，但恢复后的偶发错误不能无限期占据界面。

本次只调整主窗口底部全局通知的生命周期。首页当前录音状态、错误帮助卡、悬浮字幕和 Rust 会话状态机继续按现有逻辑显示当前状态。

## 行为规则

1. 每条新错误通知进入最近五轮保留窗口，新错误会替换旧错误并重新开始计数。
2. 一轮指一次新的录音会话开始。`idle`、`succeeded` 或 `failed` 进入 `starting` 或直接进入 `recording` 时计为新一轮；`starting` 继续进入 `recording` 不重复计数。
3. 错误产生所在轮计入五轮窗口。例如错误产生于第 N 轮，它可在第 N 至 N+4 轮期间保留；第 N+5 轮开始时自动清除。
4. 录音会话外产生的错误从显示时开始计数，在后续第 5 次新录音开始时清除。
5. 手动关闭立即清除错误及计数。后续成功、警告、信息或新错误通知仍可按现有单通知规则替换当前错误。
6. 成功、信息和警告继续使用现有定时关闭策略；错误不增加固定秒数自动关闭，避免用户尚未看完长提示就消失。
7. 五轮计数只保存在当前窗口内存中，不写入配置、日志、统计或其他本地数据；重启或重载窗口后自然清空。

## 实现边界

- 在通知策略中提供可独立测试的五轮保留规则。
- 通知 controller 在显示错误时初始化保留计数，并提供“新录音轮开始”入口；计数耗尽时复用现有 `clear()`。
- 主 controller 只在识别到真实的新录音会话边沿时通知该入口，避免同一轮多个状态事件重复扣减。
- 不增加新配置字段、依赖或用户可见文案，不改变通知 DOM 与样式。

## 测试与验收

- 先添加失败测试，证明错误在前 4 次后续录音开始时仍保留，并在第 5 次后续录音开始时清除。
- 覆盖新错误重置五轮、手动关闭重置状态、非错误通知不进入五轮计数，以及 `starting -> recording` 不重复计数。
- 运行定向 Vitest、`npm run ai:check` 和 `npm run ai:release-check`。
- 使用真实主页面验证：制造一次空识别错误，连续开始后续录音，确认第 5 轮窗口边界和关闭按钮无回退。

## 发布范围

发布版本定为 `0.10.4`。这是小范围用户可见行为修复，不改变配置、数据格式、默认策略或主链路，因此按项目版本策略升级 patch。

发布时同步五处版本来源、CHANGELOG、中英文 README 与功能 Wiki、发布审计和文档索引；构建 NSIS 安装包，记录大小与 SHA-256，在完整发布门禁通过后提交、推送、创建 `v0.10.4` 标签和正式 GitHub Release。

## 明确不做

- 不保存或展示五条错误历史，界面仍只显示最新一条通知。
- 不修改 ASR 错误判定、最终包选择、LLM 润色、剪贴板、统计、日志、热键或托盘。
- 不让空识别进入成功态，也不使用中间 ASR 文本兜底成功。
